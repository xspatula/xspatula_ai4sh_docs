eDNA metabarcoding data describes the soil microbial community per sample. It covers prokaryotes (16S rRNA, pipeline `ai4sh-16s`) and fungi (ITS, pipeline `ai4sh-its`). For what metabarcoding is and how the database stores it, read [eDNA metabarcoding][setup_db_edna] under Setup DB first.

The data arrives from the laboratory as **one Excel workbook**. That workbook is not in the repository — it contains unpublished data, and its content and layout may change as the laboratory's software develops. You place it yourself, run a conversion script, and then load the converted files with two notebooks:

```
./ai4sh/import_data/prepare_ai4sh_data/edna_final_results_to_xspatula.py   (conversion CLI)
./ai4sh/import_data/insert_ai4sh_edna_data.ipynb                           (observation log, observation, ASVs)
./ai4sh/import_data/insert_ai4sh_taxon_data.ipynb                          (taxa)
```

## Four kinds of records, six source files

| Converted file (in `./ai4sh/import_data/eDNA/excel/`) | Target process | Database table(s) |
|---|---|---|
| `AI4SH_observation_log_eDNA.xlsx` | `manage_observation_log` | `observation.observation_log` + companions |
| `AI4SH_observation_eDNA.xlsx` | `manage_observation` | `observation.observation`, `observation_measurement` (19 summary indicators) |
| `taxa_prokaryotes_singlecolumn.xlsx`, `taxa_fungi_singlecolumn.xlsx` | `manage_taxon` (bulk) | `organism_utility.taxon` |
| `AI4SH_asv_prokaryotes_eDNA.xlsx`, `AI4SH_asv_fungi_eDNA.xlsx` | `manage_edna_asv` (bulk) | `observation.edna_asv`, `observation.edna_asv_abundance` |

All six are generated by the conversion CLI. None is edited by hand.

## Required loading sequence

1. **[eDNA method catalogues]**: make sure software, taxonomy references, primer pairs, lab protocols, pipelines and pipeline steps are loaded. They are part of the utility insert chain (`insert_ai4sh_utility_data.ipynb`), so they are already in place if you completed [Load utility data].
2. **[Prepare eDNA data]**: place the laboratory workbook and run `edna_final_results_to_xspatula.py`.
3. **[Insert eDNA observations]**: the observation log, then the observations with their summary indicators.
4. **[Insert taxa]**: the taxon tree for prokaryotes (SILVA) and fungi (UNITE). This must run **before** the ASVs.
5. **[Insert ASVs]**: ASVs and their abundance per observation, followed by the verification queries.

Every step is **insert-only**: rerunning a step inserts nothing new and changes nothing. To correct an existing record, use SQL `UPDATE` or delete the record and insert it again.

## Prerequisites

- [Load sample data] must be complete. Every sample named in the laboratory workbook must exist, or be marked as excluded in the sample translator.
- The following must exist from [Load utility data]:
  - provision `ai4sh-metabarcoding` and its 19 `provision_indicator` records
  - preservation `dna/rna shield`
  - the two analysis methods `ai4sh 16s metabarcoding` and `ai4sh its metabarcoding`
- The campaigns must list `ai4sh-metabarcoding` in their `provision_id__provision_name_array` ([Manage campaign]).
- The database must include the eDNA tables and processes. After updating from an older version, rerun `setup_db.ipynb` (and its audit cell), then `setup_processes.ipynb`.
